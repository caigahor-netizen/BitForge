`GPIOA->ODR |= (1U << 5)` 看起来只是将寄存器的一位置 1。它如何让引脚输出高电平？关键是**内存映射 I/O**：GPIO 寄存器占据固定地址，处理器通过读写该地址与外设交互。

## 从代码到寄存器

```c
GPIOA->ODR |= (1U << 5);
```

在 STM32F1 的设备头文件中，`GPIOA` 指向 GPIOA 寄存器组，`ODR` 是偏移量为 `0x0C` 的输出数据寄存器。以 GPIOA 基地址 `0x40010800` 计算，ODR 地址为 `0x4001080C`。

`|=` 通常会产生一次**读—改—写**：读取 ODR，置位 bit 5，再将结果写回。下面的汇编仅示意可能的指令流程；具体指令由编译器、优化选项和目标内核决定。

```asm
LDR  R0, =0x4001080C   ; 获取 ODR 地址（示意）
LDR  R1, [R0]          ; 读取当前值
ORR  R1, R1, #0x20     ; 置位 bit 5
STR  R1, [R0]          ; 写回 ODR
```

设备头文件将寄存器声明为 `volatile`，让编译器按程序要求执行外设访问。这里的 `STR` 是 Store Register 指令；一次 C 表达式并不等于一条机器指令。

## 总线如何找到 GPIOA

处理器执行写入时，在总线上发出目标地址和数据。STM32F1 的地址译码与总线桥将访问送到挂在 APB2 上的 GPIOA，外设据此更新 ODR。CPU 使用普通的读写指令访问这个地址，但目标是外设寄存器，而非 SRAM。

示意流程：

```text
C 表达式 → 机器指令 → 总线写入 → APB2 上的 GPIOA → ODR bit 5
```

## 寄存器的值如何影响引脚

在 PA5 已配置为**通用推挽输出**且 GPIOA 时钟已使能时，ODR bit 5 参与控制输出级。写 1 时，输出级尝试将引脚拉向 VDD；写 0 时，尝试将引脚拉向 GND。

实际引脚电压取决于供电、电流负载和器件规格，不能把“写 1”无条件等同于精确的 3.3 V。若 PA5 处于输入、模拟或复用功能等其他模式，ODR 与引脚状态的关系也会不同。

如果 LED 与限流电阻从 PA5 接到 GND，引脚输出高电平且驱动能力足够时，电流流经 LED，它便会点亮。若 LED 接在 VDD 与 PA5 之间，通常是输出低电平时点亮。

## 实际编程时注意三件事

### 1. 先使能时钟并设置模式

STM32F1 需要使能 GPIOA 的 APB2 时钟，并通过 `CRL` 配置 PA5 的输出模式。下面只展示时钟使能；完整初始化还需要设置引脚模式和输出速度。

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;
```

不同 STM32 系列使用的时钟寄存器和 GPIO 模式寄存器可能不同，应以对应型号的参考手册为准。

### 2. 单个位更新优先考虑 BSRR

`ODR |=` 的读—改—写过程可能与中断或其他执行上下文中的 ODR 更新交错，导致其中一次修改丢失。STM32F1 提供 BSRR，可通过单次写入置位或复位指定引脚：

```c
GPIOA->BSRR = (1U << 5);        // 将 PA5 置 1
GPIOA->BSRR = (1U << (5 + 16)); // 将 PA5 置 0
```

BSRR 的相应位写 1 生效，写 0 不改变对应输出。这里的“原子”指单次寄存器写入完成指定的位操作；它不表示整个程序不会被中断。

### 3. 时序需要按目标器件测量

从执行代码到引脚变化的时间取决于时钟、编译结果、总线访问、输出速度设置和负载。不能用一个固定的“几十到几百纳秒”覆盖所有 STM32 和工作条件。对 WS2812 等有严格脉宽要求的接口，应依据具体时序设计，并用示波器或逻辑分析仪验证；定时器、PWM 或 DMA 通常更适合生成稳定波形。

## 小结

GPIO 输出的链条是：程序访问内存映射寄存器，处理器通过总线把写入送到 GPIO 外设，寄存器和引脚配置共同决定输出级的状态，输出级再根据供电和负载形成实际引脚电压。
